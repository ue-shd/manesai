# AGENTS.md — 最適化システムの決まりごと

このフォルダでは最適化システムを作る。エージェントは以下の決まりに従うこと。

## 起動の命令

```
uv run uvicorn app.main:app --reload
```

- 画面: http://127.0.0.1:8000/
- API の説明（/docs）: http://127.0.0.1:8000/docs

ファイル構成:
- `app/solver.py` — 計算部
- `app/main.py` — API（FastAPI）。画面も配る。入力の変換を呼ぶ
- `app/excel.py`, `app/travel.py` — 入力の変換（Excel の読み込み、地点間の移動の近似）。API 側の処理
- `app/static/` — 画面（`index.html`, `app.js`, `style.css`）
- `data/` — サンプルデータの Excel。`tools/make_sample.py` で作る
- `docs/model.md` — モデルのきまり・近似・データの出どころ
- `tests/` — pytest（`uv run pytest`）。計算部の直接呼び出しと `TestClient` で確かめる

（起動の命令やファイル構成を変えたら、この節と README.md を同時に直す）
（README.md の「今のやり方」と「利用場面」の節は利用者が書いたもの。エージェントは書き換えない）

## 決まり

### 1. Python の環境
- Python の環境は uv で管理する（`uv add` で依存を追加し、`pyproject.toml` と `uv.lock` で固定する）。
- 起動は `uv run` で始まる1行で行えるようにし、その命令を README.md と AGENTS.md に書く。
- PuLP を使うときは `pulp<4` を指定する（例: `uv add "pulp<4"`）。

### 2. 計算部
- 計算部（データを受け取り、数理モデルを組み立て、ソルバーで解き、結果と状態を返す部分）は1か所にまとめる。
- 置き場所: `app/solver.py`（移動したらここを更新する）
- Web にもファイルにも依存しない関数にする（FastAPI、HTTP、ファイル読み書き、Excel 読み込みを計算部に持ち込まない。入力は Python のデータ、出力も Python のデータ）。
- 数理モデルを書く道具とソルバー（PuLP、OR-Tools の CP-SAT、NetworkX、PyVRP など）は問題に合わせて選ぶ。**選ぶ前に候補と理由を示し、利用者に決めてもらう。**
- 採用した道具: OR-Tools の CP-SAT（候補を示して利用者が選択）。CP-SAT が時間内に解を出せないときのために、簡易な方法（店を1つずつ選ぶ手順）を計算部の中に持つ。問題を差し替えるときは改めて選ぶ。

### 3. API・MCP・画面
- API（FastAPI）と、のちに作る MCP は計算部を呼ぶだけにする。計算部を書き直したり、写したりしない。
- Excel の読み込みなど入力の変換は API 側で行い、計算部には変換後のデータを渡す。
- 画面は API を呼ぶ（画面から計算部を直接扱わない）。

### 4. 結果の状態
結果には必ず次のいずれかの状態を付ける。

| 状態 | 意味 |
|---|---|
| 最適 | 最適解が得られた |
| 最適とは限らない解 | 時間切れで途中の解を返した、または最適を保証しない解き方で得た解 |
| 解なし | 制約を満たす解が存在しない |
| 解が見つからない（時間切れ） | 時間内に解が1つも見つからなかった |
| 入力の誤り | 入力データが不正 |

- 解なしのときは表（結果の一覧）を返さず、理由を返す。

### 5. 数値
- 数値は丸めずに返す（API・計算部とも。表示上の整形が必要なら画面側だけで行う）。

### 6. 画面
- 画面は FastAPI が配る HTML にし、ビルドはしない。
- 素の JavaScript か、ビルドなしの Vue（版を固定した URL から script タグで読み込む）のどちらかを、依頼文の基本設計（画面で行う操作）を見て選び、選んだ理由をこの節に書く。
- 採用: ビルドなしの Vue（`vue@3.5.13`）。地図は Leaflet（`leaflet@1.9.4`）と OpenStreetMap。どちらも版を固定した URL から読み込む。（理由: 設定項目が多いこと、店の表を編集し店ごとに「必ず行く・行かない」を選ぶこと、複数案の切り替えに行程表・グラフ・地図が連動することから、画面の状態が多く、素の JavaScript では更新処理が複雑になるため）
- npm、React、データベース、ログインは使わない。

### 7. 利用者のデータ
- 利用者のデータは画面で入れるか、Excel をアップロードして渡す。

### 8. 実装の前の確認
- 依頼文に、数理モデル（運用中も変わらないもの）、入力、出力、評価基準のどれかが書かれていなければ、実装の前に質問する。自分で補わない。

### 9. サーバの起動と停止
- サーバの起動と停止は利用者が行う。エージェントはサーバを起動しない。
- 動作を確かめるときは、サーバを起動せずに試せる方法を使う（計算部の関数を直接呼ぶ、FastAPI の `TestClient` を使う など）。
- 作ったり直したりしたあとは、起動の命令と、開く URL（画面と /docs）を示す。
