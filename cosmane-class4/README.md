# 食べ歩きプランの最適化

使える時間・食事の回数・満腹度・疲労度・予算を設定すると、1日で食べ歩くプランの上位案を出します（サンプルは大阪キタ・ミナミの30店）。決まりごとは AGENTS.md、モデルの中身は docs/model.md を参照してください。

## 起動

[uv](https://docs.astral.sh/uv/) が必要です。このフォルダで次を実行します（初回は依存が自動で入ります）。

```
uv run uvicorn app.main:app --reload
```

- 画面: http://127.0.0.1:8000/
- API の説明: http://127.0.0.1:8000/docs

停止は起動したターミナルで Ctrl+C を押します。

## 今のやり方
- 今は、誰が、どうやって決めているか：食べ歩きをする本人（または友達グループの幹事）が、グルメサイトと地図アプリで店を探し、営業時間・移動時間・値段を1店ずつ見比べて、頭の中やメモで順番を決めている。
- どれくらい時間がかかるか：1日分の計画で1〜2時間。当日に予定が崩れると、その場で10〜20分かけて組み直す。
- 何に困っているか：
  - 着いたら閉店していた、食事の時間帯から外れていた、ということが起きる。
  - 前半で食べすぎて後半の店に入れない、歩きすぎて疲れる、など満腹度と疲労度の見通しが立たない。
  - 徒歩・自転車・バス・電車・タクシーのどれで行くと安く早いかを比べきれない。
  - 食費と移動費が予算に収まるかを、最後まで足し算しないとわからない。

## 利用場面
### 場面1
- いつ、誰が、何のために使うか：旅行の前日に、大阪へ行く本人が、1日の食べ歩きの計画を立てるために使う。
- すること：サンプルの Excel（または自分で作った同じ形の Excel）を読み込み、開始・終了の時刻と駅、食事の回数、満腹度・疲労度の上限、予算を入れて「満足度最大」で計算する。出た3案を、行程表・グラフ・地図で見比べる。
- うまくいったと言える状態：約30秒で、営業時間・食事の時間帯・予算をすべて守る案が3つ出て、そのうち1つをそのまま当日の予定に使える。

### 場面2
- いつ、誰が、何のために使うか：当日の昼に、食べ歩きをしている本人が、予定より遅れたり行くはずの店が休みだったりしたとき、残りの行程を組み直すために使う。
- すること：開始時刻と出発駅を今の時刻・今いる駅に変え、休みの店とすでに行った店を「行かない」にして、計算し直す。
- うまくいったと言える状態：残りの時間で回れる案がすぐに出る。回れる案がないときは「解なし」と、どの条件を緩めればよいかが表示される。

### 場面3
- いつ、誰が、何のために使うか：友達と行く前に、グループの幹事が、全員が行きたい店を外さずに、交通費を抑えた計画を作るために使う。
- すること：全員が行きたい店を「必ず行く」にし、目的を「移動費最小」にして満足度の下限を入れて計算する。結果の画面をグループに見せて相談する。
- うまくいったと言える状態：「必ず行く」の店がすべて入り、満足度の下限を守ったうえで、移動費が「満足度最大」の案より安い案が出る。

## データ

- サンプル: `data/sample_osaka.xlsx`（店・駅・移動手段の3シート）
- 自分のデータは、同じ形の Excel を画面から読み込みます。見本は画面右上の「Excel の見本」からダウンロードできます。
- サンプルを作り直す: `uv run python tools/make_sample.py`
